# Deep Talk Skills 内容说明

这个项目当前记录和引用的是一组“深度分析”类 skills：`pros-and-cons`、`multi-round-game` 和 `challenge-me`。三者分别对应三种不同思考模式：双向证据分析、多轮博弈推演、逆向挑战与风险控制。

| Skill | 中文界面名 | 核心用途 | 典型问题 |
|---|---|---|---|
| `pros-and-cons` | Pros and Cons 正反论证 | 对争议命题做正反双方的证据驱动分析，不输出裁决 | “这个观点有哪些支持和反对证据？” |
| `multi-round-game` | 按用户指定轮数模拟多方行动、反馈回路和状态变化 | 按用户指定轮数模拟多方行动、反馈回路和状态变化 | “用 5 轮推演这个政策/市场/竞争局面会如何演化？” |
| `challenge-me` | Challenge Me 反向挑战 | 主动寻找反证、失败机制、风险控制、验证路径和停止条件 | “挑战我的投资/创业/职业判断，告诉我哪里会错。” |

## pros-and-cons：正反论证

`pros-and-cons` 用于把用户提出的问题当成一个待检验命题，而不是默认确认它。它会先界定问题，再分别构造支持方和反对方的最强论据，并用官方记录、原始数据和可靠媒体报道支撑关键事实。最终输出以 `资料清单` 收尾，不给结论、建议、胜负判断或概率排序。

适用场景：

- 争议性公共议题、政策、历史、社会、经济、科技或战略问题。
- 用户希望看到正反双方最强论据，而不是直接获得建议或裁决。
- 需要明确区分事实、官方说法、媒体报道、推断和价值判断的问题。

默认输出结构：

1. `问题界定`
2. `共同事实与争议事实`
3. `支持该观点的论据`
4. `反对该观点的论据`
5. `证据边界`
6. `资料清单`

证据规则：

- 优先引用法律法规、法院和立法记录、统计发布、审计报告、政府或机构声明等官方记录。
- 可靠媒体可用于补充官方资料无法覆盖的报道、调查、采访和背景事实。
- 不引用搜索结果片段、Wikipedia、个人博客、社交媒体、商业 SEO 页面、无来源图表、内容农场和模型记忆。
- 学术论文、智库、NGO、书籍和百科默认只作为线索，除非用户明确扩大来源范围。

默认提示词：

```text
使用 $pros-and-cons 深入拆解这个问题，检索权威官方与媒体资料，只呈现双方论据并以清单收尾。
```

## multi-round-game：多轮博弈推演

`multi-round-game` 用于模拟一个复杂系统在固定轮数中的演化。它关注参与者、激励、约束、行动、反应、反馈回路、二阶影响和状态变量变化。每一轮必须更新博弈状态，不能只是重复罗列利弊。

适用场景：

- 用户指定了推演轮数，例如“3 轮”“5 轮”“10 轮”。
- 问题涉及多方行动和相互反应，例如市场、股价、政策、商业竞争、技术采用、地缘政治或平台生态。
- 结果会因参与者反应而改变，不适合静态正反论证。

核心流程：

1. 提取问题、轮数、时间范围、关注结果和已知约束。
2. 建立初始博弈盘：参与者、目标、资源、信息、时间范围、硬约束和状态变量。
3. 按轮次推进，从一阶影响到战略适应、交叉反馈、瓶颈、替代、路径依赖和最终状态。
4. 标注强化回路、平衡回路、延迟回路、风险转移和外生冲击。
5. 输出路径分叉、观察指标，以及事实、假设与未知项。

每轮输出字段：

- `进入状态`
- `本轮焦点`
- `各方行动与动机`
- `相互作用`
- `状态变化`
- `反作用与代价`
- `下一轮问题`

默认输出结构：

1. `推演设定`
2. `初始博弈盘`
3. `第1轮` 到 `第N轮`
4. `反馈回路`
5. `路径分叉`
6. `观察指标`
7. `事实、假设与未知项`
8. `资料清单`

默认提示词：

```text
使用 $multi-round-game 按指定轮数逐轮推演这个问题，追踪各方行动、反馈、约束和状态变化。
```

## challenge-me：反向挑战与风险控制

`challenge-me` 是刻意不对称的反方审查工具。它不会追求正反平衡，而是专门挑战用户的观点、预测、计划或决策，寻找反证、隐藏假设、基准失败、对手激励、执行风险、经济风险、规则风险、动态反馈和尾部风险，并把这些风险转化成验证路径、对冲方案和停止条件。

适用场景：

- 用户说“challenge me”“挑战我”“唱反调”“红队分析”“告诉我为什么会失败”。
- 用户已经偏向某个投资、商业、产品、职业、政策或技术判断，希望主动找错。
- 用户需要风险控制、对冲方案、证伪条件、止损或停止条件。

核心流程：

1. 精确提取用户观点、预期结果、时间范围、地区、暴露资产和已承认假设。
2. 先简短 steelman 用户观点，说明它成立必须满足哪些条件。
3. 从前提、基准率、因果、激励、执行、经济、规则、动态和尾部风险逐层攻击。
4. 为每个关键风险写明失败机制、证据强度、影响、暴露时点、早期信号、预防和限制措施。
5. 设计 Stage 0 到 Stage 4 的逐步验证路径：基线、预警、确认、行动阈值、重置条件。
6. 输出 avoid、limit、transfer、detect、respond 五类控制方案，并说明成本、失效方式和剩余风险。

默认输出结构：

1. `观点与暴露`
2. `成立所需条件`
3. `首要风险提示`
4. `反向证据与失败机制`
5. `逐步验证路径`
6. `风险控制与对冲`
7. `失败预演`
8. `风险矩阵`
9. `证伪与停止条件`
10. `仍然成立的部分`
11. `证据缺口`
12. `资料清单`

默认提示词：

```text
使用 $challenge-me 挑战我的观点，查找反向证据，并给出具体风险控制、对冲方案和逐步验证标准。
```

## 三者如何选择

- 想要“正反双方都讲清楚，但不下结论”：用 `pros-and-cons`。
- 想要“多方如何反应，局面如何一轮轮演化”：用 `multi-round-game`。
- 想要“专门找我错在哪里，并给风控和停止条件”：用 `challenge-me`。

组合使用时的推荐顺序：

1. 先用 `pros-and-cons` 建立事实和正反证据底座。
2. 再用 `challenge-me` 攻击用户最偏好的那条结论或行动。
3. 最后用 `multi-round-game` 推演各方在不同路径下如何适应和反应。

## 当前项目记录

当前项目保存了一条执行轨迹：`AI技术对个人工作者影响的双向分析框架`。该轨迹使用 `pros-and-cons` 思路，把个人工作者定义为自由职业者、独立开发者、顾问、设计师、内容创作者和个体经营者等对象，并按积极影响与消极影响组织分析框架。

该轨迹的核心研究问题包括：

- AI 是否提高个人工作者的生产率和市场机会。
- AI 是否压缩标准化服务价格、替代初级任务或削弱议价能力。
- 个人品牌、专有数据、领域知识和直连客户关系是否能保护定价权。
- 版权、隐私、错误输出、平台依赖和模型成本会如何转化为个人工作者风险。

后续可以把同一主题继续拆成三条路线：

- `pros-and-cons`：比较 AI 对个人工作者的正负证据。
- `challenge-me`：挑战“AI 会让个人工作者更强”或“AI 会让个人工作者更脆弱”的单边判断。
- `multi-round-game`：按若干轮推演个人工作者、客户、平台、模型公司、监管者和竞争者之间的动态变化。
